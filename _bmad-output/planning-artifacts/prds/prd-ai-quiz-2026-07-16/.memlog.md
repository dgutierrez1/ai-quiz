## Resolved Ambiguities (decision log)

> Every implementation choice that was ambiguous or contested during the planning conversation, settled with rationale. This is the canonical "why we did it this way" log. Mirrored from PRD Addendum B before extraction.

| Ambiguity | Resolution |
|---|---|
| Multi-answer partial scoring | **[REVISED 2026-07-16]** `clamp(round(4 × (hits − misses) / \|correct\|, 2), 0, 4)`. Fully correct = 4; empty = 0; **select-all = 0**. The prior `4 × hits / \|correct\|` ignored wrong selections, so select-all scored full marks on every `multiple` question. The old "gaming risk noted but accepted" is **withdrawn** — it was a scoring-integrity defect in the core deliverable, and the fix is ~2 lines. See FR-6. |
| Wrong-selection penalty | Wrong picks cancel right picks 1:1, then clamp at 0. Chosen over Jaccard (`4 × \|c∩s\|/\|c∪s\|`), which only *halves* select-all to 2.0 rather than killing it. |
| Partial / skipped submissions | **[NEW 2026-07-16]** Rejected. Server requires exactly one response per session question, IDs matching the session set → 400 (FR-17). Makes `weightedFinalScore`'s contiguous-position invariant hold by construction; previously undefined and would have thrown. |
| Per-question category | Single category from the **randomly-selected subset** (4–6 of the 6–10 LLM-derived candidates). Each question gets one of the selected categories; questions are **evenly distributed** (count per category differs by ≤ 1). Different runs of the same URL produce different category mixes. Hidden during the session, revealed on results |
| Category strength thresholds | `>= 3.0` strong, `>= 1.6 AND < 3.0` mixed, `< 1.6` weak (no overlap) |
| Weak-category ranking | Sort by `avgRawScore` ASC; tie-break `questionCount` DESC; then category name ASC (deterministic) |
| Category comparison | Use `avgRawScore` for category comparison (NOT `weightedScore` — position-biased, not comparable across categories) |
| Insight scope | **[REVISED]** Insight is **whole-quiz only** (FR-13 = gap_analysis). No per-question insight endpoint — per-question follow-up happens conversationally via chat (FR-10) with `questionId` anchor. |
| Correct answers leaking to FE | Stripped server-side. Chat endpoint also strips question text + correct answers from LLM context while `status='ready'` (before submit). `/insight` is gated the same way — only whole-quiz gap analysis, requires `status='submitted'`. |
| Web search on the generation path | **[NEW 2026-07-16]** **None.** Generation is closed-world: one `ssrf-safe-fetch` of `sourceUrl` (the knowledge base itself) + 1 LLM call. Tavily is confined to gap-analysis + chat, both post-quiz. Required for the FR-15 grounding check to be meaningful. |
| Token overflow | **[REVISED]** Map-reduce is **removed entirely**. Single LLM call on a chunked budget. **Tiered size limits:** 10 MB HTTP body / 2 MB decoded markdown / ~500 KB token-estimated (≈ 125k tokens, below all current model context windows). Exceeding any → `400 DOC_TOO_LARGE`. If the doc exceeds the chosen model's context window, the error includes a model-switch hint (e.g. MiniMax-M3 = 1M tokens). |
| Polling | **[NEW]** **No polling in v1.** All endpoints are sync HTTP; browser shows a spinner during the LLM call. `status='pending'` is **reserved schema space** for a future async-polling escape hatch (`202 Accepted` + `sessionId`, frontend polls `GET /api/sessions/:id` every 2–5s) — only built if sync latency ever exceeds browser timeout. |
| Strategy field | **[REVISED]** `strategy` is **required** in `POST /sessions` (enum: `factual \| comprehension \| mixed \| trivia`). The LLM uses it as a prompt modifier. No silent default; no LLM proposal. |
| LLM invalid JSON | Zod `safeParse` + **2 retries** for `jsonPromptInjection` providers + **1 retry** for strict-mode providers |
| GitHub URL variants | Accept `github.com/../blob/..` and `raw.githubusercontent.com/..`; rewrite before fetch |
| LLM provider | Provider-agnostic via Mastra (`'provider/model'` strings); user selects per session; MiniMax wired |
| Mastra + NestJS | `@mastra/nestjs` `MastraModule` imported LAST; Node `>= 22.13.0`; `@nestjs/platform-express` only |
| MiniMax model | `MiniMax-M3` (hyphen, not space); flagship |
| MiniMax structured output | `jsonPromptInjection` (no native json_schema) |
| MiniMax tool calling | Native both styles; M3 has interleaved thinking → round-trip `reasoning_details` via `extra_body={"reasoning_split": true}` (OpenAI-compat) or full `content[]` array (Anthropic-compat) |
| MiniMax caching | M3 auto-only (no explicit `cache_control`); M2.x supports explicit. M3 TTL is load-dependent, not 5min. |
| MiniMax regional | Mainland China endpoints default; international (`api.minimax.io`) via `MINIMAX_REGION=intl` |
| Prompt caching | Static prefix first; MiniMax-M3 auto-only; M2.x / Anthropic / OpenAI 5.6+ explicit `cache_control`. OpenAI 5.6+ needs `prompt_cache_key`. Anthropic workspace-isolated since Feb 5 2026. |
| Anthropic model defaults | `claude-sonnet-4-6` (NOT retired `claude-3-5-haiku`). `temperature`/`top_p` deprecated on Opus 4.7+/Sonnet 5+ — capability map must omit them |
| OpenAI model defaults | Avoid `gpt-4o`/`gpt-4-turbo`/`o1`/`o1-pro`/`o3-mini` — retire 2026-10-23 |
| Groq constraint | Structured output cannot combine with streaming OR tool use; chat flow uses text only, quiz gen uses strict mode (no stream/tools in that call) |
| User identity | **[REVISED 2026-07-16]** Browser UUID + `X-User-Id`; no auth. **HMAC binding REMOVED** — the browser had to compute `X-User-Hmac`, so `USER_HMAC_SECRET` shipped client-side and any attacker forged valid HMACs as cheaply as the app. Zero security value, plus quarterly rotation that breaks live clients. Spoofing is answered by per-route **IP-keyed rate limits**, which is what actually did the work. (Rejected alternative: server-issued signed token — real security, but contradicts browser-generated UUID and adds an issue endpoint.) |
| Rate limit keying | **[REVISED 2026-07-16]** Every route limited per-user **and** per-IP with the same table; stricter wins. The old "5 req/**sec**/IP" fallback was looser than the 30/min per-user limit it backed, handing a UUID-rotating attacker a 10× budget. In-memory store accepted — **requires `max_machines_running = 1`**. |
| `strategy` field | Enum only `['factual\|'comprehension\|'mixed\|'trivia']` — NOT free text (prompt-injection vector) |
| Insight flow | **[REVISED 2026-07-16]** Sync HTTP; insight endpoint accepts **`gap_analysis` only** (FR-12 per-question removed in 2026-07-16 round). Requires `status='submitted'` → 409 otherwise. The **"OR strip question text" escape hatch is removed** — it reopened the answer-exfiltration vector that FR-9 closes for chat, leaving `/insight` as the unguarded twin of a guarded endpoint. |
| Web search | Tavily with summarization for tool-result safety (secondary LLM call, ≤200 chars) |
| Submit idempotency | `UNIQUE (session_id, question_id)` on `user_responses`; atomic state transition guard `WHERE status='ready'`; idempotent re-submit returns cached result |
| Deploy | Vercel (web) + Fly.io (API) + Neon (DB); migrations via `fly.toml release_command`; lazy SDK loading; `/healthz` vs `/api/health` split |
| CORS | **[REVISED 2026-07-16]** Exact `WEB_ORIGIN` always; `WEB_ORIGIN_REGEX` applies **only when `NODE_ENV !== 'production'`**. The archive's `x-vercel-environment: production` gate is **removed** — that header lives inside Vercel's runtime and is never present on a cross-origin browser request to Fly, so the check could not function. |
| Mastra + NestJS (Node) | **[CLARIFIED 2026-07-16]** Node `>= 22.13.0` → Docker base image **`node:22-slim`**. The archive's `node:20-slim` is **wrong** and build-breaking (fails `engines`, breaks Mastra in prod). |
| Document storage | Full markdown + chunks in DB; SHA-256 hash for integrity |
| Chat persistence | `chat_messages`; restored on history revisit; pagination by `(created_at, id)` cursor |
| Result UI | Dual-panel on desktop; tab-based on mobile (<md); per-question "Explain" button seeds chat |
| SSRF | Custom safe-fetch with DNS-pinning, expanded IP blocklist, redirects off, IDN homograph rejection, HTTP/0.9 rejection |
| Per-endpoint ownership | **[REVISED 2026-07-16]** `@OwnsSession()` interceptor + app-layer `WHERE user_id = ?` + 404 for both not-found and not-owned. **RLS REMOVED** — the policies could not have worked as written (`documents`/`questions`/`answers`/`user_responses`/`knowledge_categories` have **no `user_id` column**, and without `FORCE ROW LEVEL SECURITY` the Neon table-owner role bypasses RLS entirely). Dropping an illusory control costs ~no security and deletes the `SET LOCAL` interceptor + the pooler question. The isolation **test stays**, reframed from RLS to ownership. |
| Prompt injection | **[REVISED 2026-07-16]** Trust-boundary prompts + **deterministic ingest neutralization** (FR-15) + Tavily summarization. **Heuristic regex removed** (theatre). Ingested markdown is inert data — the only execution surface is the chat tool loop, whose blast radius is bounded (one read-only tool, ≤2 iterations, no secrets/PII/auth in context). **No LLM rewrite of source content** — a rewrite pass is itself injectable, costs a doc pass on the critical path, and destroys the fidelity quizzes need. |
| LLM output safety | **[REVISED 2026-07-16]** Zod length caps + **structured output as containment** + **plain-text Q/A rendering** (no markdown → no XSS path) + **grounding check** + **secret-shaped-token check relative to source** + refusal handling + DOMPurify scoped to explanations/chat only. **`outputLooksUnsafe` keyword blocklist REMOVED** (`DROP TABLE`/`password`/`<script>`) — it false-positived on exactly the DB/security READMEs this app targets, marking legitimate sessions `failed`, while protecting nothing the other controls don't. |
| NestJS hardening | helmet + CORS allowlist + body limits + SafeExceptionFilter + per-user throttler |
| Postgres | **[REVISED 2026-07-16]** TLS required; statement/query timeouts; UNIQUE constraints for idempotency. **No RLS** (see "Per-endpoint ownership"); no `SET LOCAL app.user_id` transaction interceptor. |
| Deps | pnpm audit + Renovate + CycloneDX SBOM |
| Secrets | Env-only; pino redaction (denylist with allowlist for log fields); Langfuse content scrubbing (cron-driven, not policy-only) |
| FE state | TanStack Query (server) + React Context + `useState` + `useLocalStorage` (client). No Zustand — overkill for this scope. |
| E2E tests | Playwright + POM; `data-testid` selectors only |
