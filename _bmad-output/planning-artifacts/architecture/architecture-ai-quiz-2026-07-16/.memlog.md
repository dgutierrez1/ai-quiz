- (decision) AD-1 paradigm=Hexagonal Architecture. Binds: apps/api/src/* (entire backend). Prevents: domain logic coupled to NestJS/Drizzle/Mastra; cross-boundary types duplicated. Rule: domain/ ports/ use-cases are pure; adapters and driving layer hold all I/O. -- [ADOPTED from SPEC.md §4]
- (decision) AD-2 domain_purity: apps/api/src/domain/ imports nothing from @nestjs/_, drizzle-orm, mastra, undici, node:fetch. Binds: apps/api/src/domain/_ + all use-cases. Prevents: I/O leaking into pure logic; tests becoming slow/integration-y. Rule: enforced by ESLint no-restricted-imports rule plus domain tsconfig with separate package boundary.
- (decision) AD-3 zod_dto_boundary: All cross-boundary types are Zod-inferred DTOs (z.infer of X), Object.freeze-wrapped at construction. Binds: HTTP to domain, domain to adapter, adapter to domain. Prevents: any/unknown leaking across layers; runtime shape drift. Rule: never pass plain objects across boundaries; always parse + freeze.
- (decision) AD-4 llm_untrusted: LLM outputs are untrusted. Binds: every adapter that calls an LLM. Prevents: malformed JSON, refusal strings, injection-shaped strings reaching persistence/UI. Rule: Zod safeParse + 2 retries (best-effort providers) / 1 retry (strict-mode); UntrustedLlmOutputError on final failure; session marked failed.
- (decision) AD-5 llmport_only: Only LlmPort (apps/api/src/domain/ports/LlmPort.ts) calls LLM adapters. Binds: all LLM-touching code. Prevents: bypass of capability map, caching, retry, output validation. Rule: use-cases never import from adapters/llm/* directly.
- (decision) AD-6 provider_agnostic_mastra: Mastra resolves LLM providers via env vars and 'provider/model' string format. Binds: LLM adapter, runtime config. Prevents: hardcoded provider SDK in domain; per-provider auth leaks. Rule: LLM_MODEL default 'groq/openai/gpt-oss-20b'; MiniMax wired via inline url form (not built-in Mastra provider).
- (decision) AD-7 mastra_catchall_last: MastraModule.register({mastra}) MUST be imported last in AppModule imports. Binds: apps/api/src/app.module.ts. Prevents: catch-all @All('*') shadowing all NestJS controllers (returns 404 for every endpoint). Rule: integration test asserts every NestJS route resolves; comment in app.module.ts above MastraModule explaining the constraint.
- (decision) AD-8 runtime_constraints: Node >= 22.13.0 (pin in package.json engines); @nestjs/platform-express only (Mastra adapter does not support Fastify). Binds: apps/api runtime, deploy target. Prevents: Mastra integration failure; silent Fastify incompatibility. Rule: CI fails on Node <22.13.0; lock @nestjs/platform-express as direct dep.
- (decision) AD-9 rls_per_request: All /sessions/:id/* routes verify ownership via @OwnsSession() interceptor + Postgres RLS. Binds: all session-scoped endpoints. Prevents: IDOR (S2); cross-user data leak. Rule: interceptor opens transaction with SET LOCAL app.user_id = '<validated-uuid>'; RLS policies on ALL user-owned tables (quiz_sessions, chat_messages, insights, documents, questions, answers, user_responses, knowledge_categories); returns 404 (not 403) for both not-found and not-owned.
- (decision) AD-10 ssrf_expanded: HttpMarkdownAdapter implements SSRF defense with expanded IP blocklist. Binds: IngestionPort. Prevents: SSRF to RFC1918 + CGN (100.64/10) + Oracle IMDS (192.0.0/24) + benchmarking (198.18/15) + multicast + reserved + IPv6 ULA + 6to4 (2002::/16); IPv4-mapped IPv6 bypass; IDN homograph; HTTP/0.9 smuggling. Rule: scheme allowlist https/http only; hostname blocklist (localhost, metadata.*); net.isIP() for literals; normalize ::ffff:a.b.c.d then a.b.c.d before RFC1918 check; DNS-pin-then-validate; bind undici Agent to validated IP; reject punycode mismatch; disable redirects; 10MB cap; 10s timeout; text/markdown or text/plain only.
- (decision) AD-11 identity_hmac: X-User-Id spoofing mitigated via HMAC binding + IP-fallback rate limit. Binds: every authenticated endpoint. Prevents: per-user rate limit bypass via UUID rotation (S5). Rule: client sends X-User-Hmac = HMAC(USER_HMAC_SECRET, userId||timestamp); server verifies and rejects if older than 5min; IP-fallback 5 req/sec/IP regardless of UUID.
- (decision) AD-12 chat_pre_submit_guard: Chat endpoint while session.status='ready' strips question text + correct answers from LLM context. Binds: POST /api/sessions/:id/chat. Prevents: answer-exfiltration before submit (S1). Rule: use-case checks status; ChatUseCase receives redacted QuestionDto if status='ready'; full DTO if status='submitted'.
- (decision) AD-13 tavily_dual_llm: Tavily web search results are summarized by a secondary LLM call to <=200 chars before being added to the main agent's context. Binds: WebSearchPort implementation; chat flow with tools. Prevents: tool-result poisoning (indirect prompt injection). Rule: summarizer cannot invoke tools; raw HTML/markdown never crosses the boundary; summarizer uses different provider than main agent when possible.
- (decision) AD-14 drizzle_only_persistence: Drizzle ORM is the only persistence path; raw SQL via sql tag is allowed only inside adapters and must use parameterized queries. Binds: all DB-touching code. Prevents: SQL injection; data-access duplication. Rule: no other ORMs/raw pg client; migrations via drizzle-kit; sql template tag uses $1/$2 placeholders.
- (decision) AD-15 submit_idempotency: user_responses has UNIQUE(session_id, question_id); submit transitions quiz_sessions atomically via UPDATE WHERE status='ready' RETURNING. Binds: POST /api/sessions/:id/submit. Prevents: double-scoring on retry/duplicate POST; lost responses. Rule: DB constraint plus transaction wrapper; concurrent submits return the cached result (idempotent).
- (decision) AD-16 multi_answer_scoring: Multi-answer scoring = round(4 * |correct intersect selected| / |correct|, 2), capped at 4. Binds: scoring module in packages/shared. Prevents: multi-answer questions never scoring 4; NaN from empty input. Rule: full-correct yields 4; empty yields 0; throws on n<=0; type='single' requires exactly 1 correct; type='multiple' requires 2..4 correct; positions validated as unique integers in [0,3].
- (decision) AD-17 fe_state_split: Server state owned by TanStack Query v5; client state via React Context (UUID/theme) + useState per-component + custom useLocalStorage hook for prefs. Binds: apps/web state management. Prevents: state store bloat; SSR hydration mismatches; cross-component prop drilling. Rule: no Zustand, no Redux; query-keys factory in apps/web/lib/queries.ts; UUID generated + persisted in top-level script before React hydrates.
- (decision) AD-18 lazy_sdk_loading: Provider SDKs are dynamic-imported in LlmAdapter on first use. Binds: apps/api/src/adapters/llm/*. Prevents: 256MB Fly free-tier OOM; 150MB baseline from loading 5 SDKs. Rule: default provider (groq) loaded eagerly; others via await import() in MastraLlmAdapter per call; /api/health exposes process.memoryUsage() in non-prod.
- (decision) AD-19 deploy_topology: Vercel (web) + Fly.io (API) + Neon (DB). Binds: deployment + cost ceiling. Prevents: violating $0/mo mandate. Rule: env vars via fly secrets set + Vercel per-env; migrations via fly.toml release_command; node:20-slim base image; auto-stop Fly machines with cron ping /healthz every 4min (min_machines_running unavailable on free tier).
- (decision) AD-20 health_endpoints: Two health endpoints split by purpose. Binds: Fly healthcheck + monitoring. Prevents: Fly kill-loop when Neon is cold (P5). Rule: GET /healthz is process-alive (~1ms), used by Fly healthcheck (timeout 30s, grace 60s, interval 30s); GET /api/health deep-checks DB + provider reachability, used by monitoring; Drizzle init wrapped in 5-attempt retry loop with exp backoff.

- (decision by user) SUPERSEDES AD-9 rls_per_request: RLS is REMOVED. Ownership = @OwnsSession() interceptor + app-layer WHERE user_id = ? + 404 for not-found AND not-owned. No SET LOCAL app.user_id, no RLS policies, no transaction interceptor. Reason: policies could not work as written — documents/questions/answers/user_responses/knowledge_categories have no user_id column (join via session_id); and without FORCE ROW LEVEL SECURITY the Neon table-owner role bypasses RLS entirely. Control was illusory. Interceptor + app filter is now the SOLE defense and must be airtight. Isolation test stays, reframed from RLS to ownership.
- (decision by user) SUPERSEDES AD-11 identity_hmac: HMAC binding REMOVED. No X-User-Hmac header, no USER_HMAC_SECRET, no rotation. Reason: the browser had to compute it, so the secret shipped client-side and forging was free — zero security value plus quarterly rotation that breaks live clients. Replacement: every route rate-limited twice, once keyed by X-User-Id and once by IP, same table, stricter wins (global 30/min, POST /sessions 5/min, /insight 10/min, /chat 20/min). The old 5 req/sec/IP fallback is ALSO removed — it was looser than the 30/min per-user limit it backed (300/min vs 30/min), giving a UUID-rotating attacker a 10x budget. In-memory throttler store accepted but REQUIRES max_machines_running = 1.
- (decision by user) SUPERSEDES AD-19 deploy_topology (base image only): node:22-slim, NOT node:20-slim. Reason: Mastra requires Node >= 22.13.0, so node:20 fails the engines check and breaks the API in prod. Rest of AD-19 (Vercel + Fly + Neon, fly secrets, release_command migrations, auto-stop + cron ping /healthz) stands, PLUS max_machines_running = 1 is now REQUIRED for rate-limiter correctness.
- (decision by user) SUPERSEDES scoring AD (was: round(4 x |correct AND selected| / |correct|, 2) capped at 4): multi-answer is now clamp(round(4 x (hits - misses) / |correct|, 2), 0, 4) where hits=|correct AND selected|, misses=|selected NOT IN correct|. Wrong picks cancel right picks. Fully-correct=4, partial=proportional, hit+miss=0, SELECT-ALL=0, empty=0. Reason: the old formula ignored wrong selections, so selecting all 4 options scored FULL MARKS on every multiple question — a scoring-integrity defect in the core deliverable, not an accepted trade-off. Chosen over Jaccard, which only halves select-all to 2.0. Also NEW: submissions must be complete (one response per question, IDs matching session set, else 400) which makes weightedFinalScore's contiguous-position invariant hold by construction.
- (decision by user) NEW (no prior AD): FR-15 ingest neutralization + output grounding. Ingested markdown is inert data; only execution surfaces are the generator LLM (content integrity) and the chat tool loop (bounded, accepted). Ingest: deterministic LLM-free scrub — strip HTML comments/raw HTML/link titles/alt text/base64 blobs, NFKC normalize, strip control+zero-width+bidi chars, PRESERVE code blocks. Output: structured output is the containment; Q/A render as PLAIN TEXT never markdown; DOMPurify scoped to explanations+chat only; grounding check rejects questions with no token overlap vs source chunks; secret-shaped-token check relative to source.
